# Meshy rock reference prototype

The six-model set is now integrated into normal mobile-mode gameplay.
The historical art fixtures below remain available. No new APK was built.

## Runtime integration

- `tools/bake_mobile_rocks.gd` extracts and normalizes geometry into twelve small
  resources under `assets/mobile/rocks/`: six near meshes and six simplified
  distant meshes. Source GLB textures are not referenced by these resources.
- `mobile_rock_library.gd` caches the meshes and shares one bedrock material.
- Intact 2x2 rock areas use broad formations. Areas within one cell of excavation
  use smaller, lower formations with a setback from the masonry. Group membership
  is part of the cell signature, including diagonal excavation changes.
- Core placement previews also hide intersecting groups originating outside the
  preview footprint. The simulation and dig costs are unchanged.
- `mobile_backdrop.gd` replaces the old plates with six MultiMesh batches and a
  continuous low underlay. Camera limits and the explicit wall toggle remain.
- Android export selections include the twelve baked resources and library.

The local Vulkan memory probe (600 camera frames, then 300 raid frames) reported
92.48 MiB static memory after loading and 92.60 MiB after the raid. Texture memory
stayed at 151.38 MiB, with 1003 nodes and 297 resources. This is desktop evidence,
not Pixel performance validation. Runtime environment captures are generated by
`tools/capture_environment.gd`, not by the isolated prototype script.

- Reference: `production/meshy_assets/walls/rock_formation_reference_v1.png`
- Model: `assets/models/walls/rock_formation_reference_v1.glb`
- Meshy task: `01a0fb6d-dbb5-749a-8ea6-548aded86a59`
- Actual geometry: 2,418 triangles per instance; eight instances in this fixture.
- Material: shared existing bedrock texture and rock shader override. Original
  embedded materials remain available in the source GLB.
- Script: `tools/probe_rock_module.gd`, launched with the mobile Vulkan renderer.

The fixture creates a paused, save-independent corridor. One module is repeated
with different rotations and heights beyond a low transition strip. The old
procedural terrain remains as a temporary background. Both wall states are
captured at camera angles 45 and 135 degrees under `artifacts/meshy-rock-prototype-*`.
Fit assertions check the requested footprint and height using forward transforms.

Verified locally in Godot 4.7.2 with Vulkan: all four captures were produced,
with no reported script errors. Mobile device performance has not been measured.
The imported source textures are still 2048px; production integration needs a
texture budget pass and multiple distinct silhouettes after visual approval.

Do not treat this isolated prototype as a completed match to the concept art.
The repeated silhouette and large background plates remain visible limitations.

## Two additional variants

- `rock_crag_high_v1.glb`: asymmetric high shoulder, 2,499 triangles.
  Meshy task `01a0fb92-5a2a-77aa-825a-670468d1902d`.
- `rock_shelf_low_v1.glb`: broad low shelf, 2,470 triangles.
  Meshy task `01a0fb93-117f-724c-8cb9-726e857d8408`.
- Matching reference PNGs are in `production/meshy_assets/walls/`.

Run the same fixture with `-- --variants` after Godot's arguments to use all
three models. Captures are saved as `artifacts/meshy-rock-variants-{state}-{yaw}.png`
without overwriting the original comparison images. Normal gameplay is unchanged.

Verified: import completed without reported errors; footprint/height assertions
passed for every instance; four Vulkan captures produced. Inspected both camera
angles with walls shown and the 45-degree hidden-wall view. The Meshy Python
pipeline suite passed 24 tests. No new phone performance test or APK build.
